## 1. 产品概述

### 1.1 一句话定位

面向个人用户的 **Apple 全平台记账工具**：一次记账、三端可见，数据只存在本地设备上。

### 1.2 目标用户与典型场景

| 用户 | 场景 |
|------|------|
| 日常记账的个人用户 | 买完东西 10 秒内完成一笔记录（金额 → 分类 → 备注） |
| 想在腕上快速记账的用户 | 抬腕选出分类、输入金额，回到手机自动出现该笔账单 |
| 需要复盘消费结构的用户 | 在趋势页看支出/收入的分类占比与活跃度，判断钱花在哪 |
| 关心隐私的用户 | 开启应用锁后，切到后台不会在多任务卡片暴露账单内容 |

### 1.3 设计原则

1. **本地优先**：账单与账号数据只保存在设备本地（Core Data / SwiftData），当前无任何服务端上传。
2. **零第三方依赖**：不引入 SPM / CocoaPods 依赖，图片等能力自研。
3. **四语言一致性**：简体中文 / 繁體中文 / English / 日本語 四套文案必须 key 齐备（脚本校验）。
4. **隐私默认安全**：应用锁开启后，进后台整页高斯模糊；密码只存哈希与盐。
5. **平台各自最适**：三端共用交互语言但各自实现（不做跨端抽象层），Watch 只做「看今天 + 快速记账」。

## 4. 业务规则（跨模块）

| 编号 | 规则 |
|------|------|
| RUL-01 | **类型与分类必须匹配**：支出只能取 25 个支出分类，收入只能取 11 个收入分类，转账分类固定为 `transfer`；编辑页切换类型会清空分类并要求重选 |
| RUL-02 | **金额规则**：键盘输入支持四则运算（按从左到右计算）；单笔小数最多 2 位、整数最多 9 位；保存金额必须 > 0 |
| RUL-03 | **数据隔离**：账单归属由 `Bill.createdBy == 当前登录标识` 决定，所有账单查询与统计都必须带该过滤 |
| RUL-04 | **账号与密码**：密码 ≥ 6 位，仅保存 `SHA256("盐|密码")` 与随机盐；会话 7 天；注销会彻底删除该账号数据 |
| RUL-05 | **统计口径**：今日 = 当天；本月 = 当前自然月至今；上月 = 完整上一自然月；本年 = 今年 1 月 1 日至今（YTD）；笔数含收入与支出，转账计入笔数但不计入收支 |
| RUL-06 | **时间精度**：账单时间精确到分钟；列表按自然日分组，统计按自然日/自然月/自然年聚合 |
| RUL-07 | **本地化规则**：新增文案必须走 `L10n.string`；四语言 key 集合必须完全一致；语言切换会同步系统语言偏好并重启进程 |
| RUL-08 | **隐私规则**：开启应用锁后进后台整页模糊；被遮挡内容对 VoiceOver 隐藏 |
| RUL-09 | **Watch 写入**：以 `id`（UUID）幂等去重；`userIdentifier` 为空或 `anonymous` 时归到当前登录用户 |
| RUL-10 | **数据导出**：CSV 表头固定 `date,type,category,amount,note`；导入仅接受 `income / expenditure / transfer` |

## 5. 数据模型（需求视角）

**Bill（账单）**：`id`(UUID，幂等键) / `amount`(Decimal) / `type`(`expenditure`·`income`·`transfer`) / `category`(分类 rawValue) / `note`(备注) / `date`(记账时间) / `createdBy`(归属账号) / `createdAt` / `updatedAt` / `updatedBy`

**UserProfile（用户）**：`userIdentifier`(邮箱 / 手机号 / Apple ID) / `email` / `phone` / `passwordHash` / `passwordSalt` / `provider`·`providerID` / `nickname` / `signature`(个性签名，≤40 字) / `avatarData`(头像) / `monthlyBudget`(月度预算) / `createdAt`·`updatedAt`

**TodoItem（待办）**：`id` / `title` / `note?` / `dueDate?` / `priority`(0 无·1 低·2 中·3 高，`Int16`) / `isDone` / `completedAt?` / `repeatRule`(`none`·`daily`·`weekly`·`monthly`·`yearly`) / `createdAt`·`updatedAt` / `createdBy`·`updatedBy`；关系 `subtasks`(一对多，级联删除)、`tags`(多对多)

**TodoSubtask（子任务）**：`id` / `title` / `isDone` / `createdAt` / `owner`(所属待办)；仅一层，不支持嵌套

**TodoTag（标签）**：`id` / `name` / `colorIndex`(`Int16`，取 8 色板下标) / `createdBy` / `items`(多对多反向)

**MemoNote（备忘）**：`id` / `title?` / `content` / `isPinned` / `createdAt`·`updatedAt` / `createdBy`·`updatedBy`

**AssetAccount（资产账户）**：`id` / `name` / `type`(`cash`·`debitCard`·`creditCard`·`payment`·`investment`·`other`) / `balance`(Decimal，可负) / `note?` / `includeInTotal` / `sortOrder`(`Int16`) / `createdAt`·`updatedAt` / `createdBy`·`updatedBy`

**AssetSnapshot（资产快照）**：`id` / `date`(当天 00:00) / `totalAssets`(Decimal) / `totalLiabilities`(Decimal) / `createdAt` / `createdBy`；每个自然日一条，同日覆盖写

> 三份模型契约一致：iOS / macOS 两份 `.xcdatamodeld` 与 SwiftData 版 `iFinanceSwiftData/Data/TodoEntities.swift`、`AssetEntities.swift`。Core Data 的非标量属性（String / Date / Decimal）生成为可选类型，SwiftData 侧为对应非可选字段。

## 7. 已知限制与未实现（含启用条件）

### 7.1 CloudKit 同步与本地通知（💤 禁用）

- 现状：`CloudKitSyncManager`、`NotificationManager` 为保留结构的 stub，所有系统调用已注释，UI 入口仍在。
- 原因：需要付费开发者账号（CloudKit 容器与推送能力）。
- 启用条件：升级开发者账号 → 恢复 `CloudKit` / `UserNotifications` 调用 → 数据模型切换为 `NSPersistentCloudKitContainer` 或自建同步方案。

### 7.2 微信 / QQ 登录（🚧 未开放，已降级为提示）

- 现状：按钮保留外观，点击仅提示「即将支持」，**不再创建占位账号**；`AuthManager.loginWithProvider` 仅放行 `.apple`，从数据层杜绝微信/QQ 影子账号。
- 依赖：微信开放平台（需企业主体与 300 元/年认证）与 QQ 互联（免费但需审核）资质、**服务端**用 AppSecret 换 token、URL Scheme / Universal Link 配置。
- 真实接入时：移除视图提示与 `loginWithProvider` 的 `.apple` 限制，按开放平台 SDK 回调获取稳定标识。

### 7.3 邮箱验证码绑定（💤 未实现）

- 现状：绑定邮箱只需验证密码，无验证码流程。
- 依赖：服务端下发与校验 + 发信服务（免费额度即可）+ 发信域名（SPF/DKIM）。

### 7.4 macOS CSV 导出（💤 TODO）

- 现状：`MaciFinance/Views/SettingsView.swift` 中标注 TODO，仅 iOS 两版支持 CSV 导入导出。

### 7.5 Watch 离线不补传（🚧）

- 现状：iPhone 不可达时账单只写入 Watch 本地缓存，不会在恢复连接后自动补发；用户需重新记账。
- 建议：后续增加队列 + 重连重试（`transferUserInfo` 本身可靠，可在可达时统一补发）。

### 7.6 其它

- 无埋点与崩溃上报（依赖本地 `Logger` 与系统诊断报告）。
- iPad 未做分栏/多窗口适配（当前以内容最大宽度居中的方式适配大屏）。
- 主版本 iOS 与 SwiftData 版视图代码为双份副本，改动需同步两处（有约定与文档，但无自动校验）。

## 9. 验收清单（回归用）

1. 注册 → 登录 → 记一笔支出 → 概况页今日结余与笔数变化正确
2. 记一笔带小数的支出并在键盘上做四则运算，保存金额等于运算结果
3. 编辑账单：把支出改成收入 → 分类被清空且保存置灰 → 选收入分类后可保存
4. 编辑账单：日期可分别选到年月日与时分；转账时分类行只读「转账」
5. 账本筛选（本日/本周/本月/本年 + 分类 + 关键词）结果正确，行显示备注为主
6. 预算：设置预算 → 环形进度与「已用 X%」（最多两位小数）与分类占比正确
7. 趋势：切跨度后柱状趋势与两张分类饼图同步更新；点选扇区高亮；热力图点击显示笔数
8. 设置：切换主题与语言（重启后全站文案跟随）；开启应用锁后进后台快照模糊
9. 个人中心：更换头像（可拖动缩放）、修改昵称/个性签名/邮箱/手机号/密码
10. CSV 导出 → 清空数据 → 导入，账单条数与合计一致
11. Watch 记一笔 → iPhone 账本出现（且不重复）；Watch 断开时提示使用缓存
12. 四端编译通过、三套测试全绿、本地化审计脚本通过
13. 待办：新建一条带截止日与重复规则的待办 → 到期分组正确 → 勾选完成后自动生成下一期（子任务重置为未完成）
14. 待办：勾选 / 取消勾选、滑动删除、清除已完成（二次确认）都即时生效；标签超过 12 个或重名时给出提示
15. 备忘：新建 → 置顶后排在最前 → 编辑与滑动删除正常；标题与正文同时为空时禁止保存
16. 资产：账本页右上角进入资产页 → 新建两个账户（含一个负余额信用卡）→ 总资产 / 负债 / 净资产与账户数正确 → 环形图与明细占比对应
17. 资产：再改一次余额 → 「较上次变化」显示金额与百分比；同日多次修改只覆盖当天快照（不新增多条）
18. 待办 / 资产在**两版 iOS App 上表现一致**（主版本与 SwiftData 版）
19. 待办：有子任务的条目点「2/5」原地展开 → 直接勾选子任务 → 收起后进度更新（不进入编辑页）
20. 待办：编辑页「管理标签」→ 重命名一个标签（待办上的标签名同步变化）→ 删除一个标签（待办保留、标签消失）
21. 备忘：正文输入 `# 标题`、`- [ ] 待办`、`**重点**` → 切到「预览」看到标题 / 勾选框 / 粗体；工具栏按钮在选中文字上生效
22. 账本：只修改一笔账单的金额 → 返回列表当日净额与预算卡「已用」同步变化

| 隐私遮罩 | 进后台时对整页做的高斯模糊（仅在开启应用锁时生效） |
