# 协作约定（与用户的配合方式）

> 记录本次协作中形成的习惯与教训，供下一轮对话直接沿用。用户需求若有变化，以用户当场指令为准。

## 1. 沟通方式

| 约定 | 说明 |
|------|------|
| 语言 | 全程中文；代码注释、提交信息、文档都用中文 |
| 需求先澄清再动手 | 用户偏好「一问一答」把需求具象化（工具不支持弹选项时用文字提问）；重要歧义必须先确认 |
| 方案先行 | 复杂需求先给出完整方案（含取舍与验收标准）供审核，确认后再实施 |
| 进度可见 | 执行过程中持续给简短更新（在做什么、发现什么、下一步），不要长时间沉默 |
| 结论先行 | 汇报时先说结果，再给证据（数据/日志/命令输出），不要只描述过程 |

## 2. 交付与提交

1. **分支**：默认使用 `codex/` 前缀分支（本次为 `codex/platform-18-27`）；**不推送远端**，由用户 review 后决定。
2. **提交粒度**：分阶段提交（功能与视觉 / 性能 / 文档 各自独立），提交信息用中文并写清「做了什么 + 怎么验证的」。
3. **验证四件套**（本次固定下来的标准动作；**2026-09-26 用户指示：不强制跑全套单测，"基本功能能用就行"**，此时至少保留四端编译 + 本地化审计 + 启动冒烟）：
   - 四端编译通过；
   - 三套测试**串行**全绿（iOS / SwiftData / macOS）；
   - `python3 scripts/check_localization.py` 通过（改过文案时必跑）;
   - 模拟器安装 + 启动冒烟（必要时三尺寸：iPhone SE / iPhone 16 / iPad）。
4. **文档同步**（用户明确要求）：改功能 → 更新 `docs/PRD.md` 状态列与 `memory/work-history.md`；改接口/数据模型/Watch 协议 → 更新 `docs/api/*`；踩到新坑 → 写进 `AGENTS.md` 坑表与 [decision-log.md](decision-log.md)。

## 3. 代码约定（用户明确要求过的）

| 约定 | 来源 |
|------|------|
| 新写 UI **不许写魔法数字**，用 `AppSpacing` / `AppRadius` / `AppLayout` / `AppTypography` / `AppMotion` | D-10 / D-11 |
| 新增文案**必须用 `L10n.string`**（不要 `String(localized:)`） | D-25 |
| 百分比展示用 `AppNumberFormat.percent`（最多两位小数、去尾零） | D-32 |
| 背景动画只用 `AppBackgroundView`（内部共享时钟），不要新写 `TimelineView(.animation)` | D-28 |
| 头像解码走 `AvatarImageCache`，不要在 body 里 `UIImage(data:)` | D-29 |
| `NumberFormatter` / `DateFormatter` 一律 `static let` | D-29 |
| 账单 `type` 与 `category` 必须匹配（走 `BillEditRules`），分类不允许自由文本 | D-41 |

## 4. 用户的关注点（做取舍时优先考虑）

1. **观感与一致性**：卡片风格、间距、灰阶可读性、动效节奏；曾因为"灰色字看不清""名言样式太丑""卡片内容太少"提出多轮修改。
2. **性能与跟手感**：明确反馈过「切页面 / 开键盘卡顿」与「真机部署慢」，并接受为此做大范围重构（共享时钟、缓存、子视图拆分）。
3. **国际化正确性**：不能出现原始 key、不能漏翻译、切换语言后必须全线跟随。
4. **交互合法性**：拒绝"技术上能保存但业务上不合理"的数据（如收入带餐饮分类）。
5. **隐私**：主动要求后台模糊，且明确"只在开启 Face ID 验证时启用"。
6. **真机体验**：会直接在真机上验证，因此构建/部署效率也是体验的一部分。

## 5. 教训（我犯过的错，避免重犯）

| 教训 | 具体经过 | 改进 |
|------|----------|------|
| **不要用 `git add -A`** | 提交"今日结余"改动时，`git add -A` 把用户正在 Xcode 里新建的**空图片集** `MyWechatNew.imageset` 一起提交了 | 提交前先 `git status` 核对；只添加本次相关路径，必要时用 `git add -p` |
| 机械替换要留校验 | 批量替换 `String(localized:)` 时，需排除 L10n 自身实现文件（那里的 `NSLocalizedString` 就是实现） | 替换脚本显式 skip 列表 + 替换后 `rg` 复查 |
| 改完文件要立刻编译 | 一次编辑把 `ProfileView` 尾部弄出重复函数，靠"大括号计数 + 编译"才发现 | 大改动后立即 `xcodebuild build` 验证，不要攒到最后 |
| 单测断言要考虑环境残留 | `LocalizationSync` 测试最初假设 `AppleLanguages` 初始为 nil，但系统域会提供默认值，且模拟器残留 `app_language=ja` 导致偶发失败 | 断言前先置为确定状态；读取用 App 自身持久域（`persistentDomain(forName:)`） |
| 时间/日期相关逻辑要覆盖跨年 | 周期概况的"上月"在 1 月会落到去年 12 月，必须显式测跨年 | 新增聚合逻辑必须有跨月/跨年用例 |

## 6. 沟通模板（用户习惯的节奏）

> 用户常以「先描述需求 → 让我逐个提问 → 出方案 → 执行」的方式推进；也会在任务进行中插入「顺带修一个 bug」。插入的需求默认并入当前工作，一起验证、一起提交（除非用户另行说明）。
